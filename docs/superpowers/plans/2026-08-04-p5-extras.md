# P5 Extras Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete approved P5 extras and safely execute the deferred SEO migration follow-up for the portfolio subdomain.

**Architecture:** The site has one code-owned canonical origin (`SITE_URL`) and one Cloudflare-owned legacy redirect. SEO submission is an owner-gated external operation: public HTTP evidence is recorded first, then the owner submits the canonical sitemap to verified search-engine properties, and reviews defined signals against a baseline.

**Tech Stack:** Next.js 16 metadata routes, Cloudflare Workers Single Redirect Rules, Google Search Console, Bing Webmaster Tools, curl, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-04-p5-extras-design.md`

## Global Constraints

- Canonical production origin is exactly `https://portfolio.huynhsang.id.vn`.
- `https://huynhsang.id.vn` is not a Worker custom domain; it is an exact-host Cloudflare `308` redirect that preserves path and query.
- Sitemap source of truth is `https://portfolio.huynhsang.id.vn/sitemap.xml`; never submit an apex sitemap.
- Do not store Search Console, Bing, Cloudflare, or analytics credentials/API tokens in the repository.
- Search-console submission, DNS changes, redirect changes, deployment, and rollback are owner-gated remote operations. Get explicit authorization immediately before each external mutation.
- Daily DX is `bun run dev`; Workers-true evidence is `bun run deploy` followed by remote smoke. Do not make local `bun run preview` a gate.

### Task 1: Verify public canonical evidence before submission

**Files:**

- Inspect: `src/config/site.ts`
- Inspect: `src/app/robots.ts`
- Inspect: `src/app/sitemap.ts`
- Inspect: `tests/unit/canonical-origin.test.ts`
- Record: owner-maintained P5 migration log (external evidence; no repository secret)

**Interfaces:**

- Consumes: `SITE_URL = "https://portfolio.huynhsang.id.vn"` and the deployed Cloudflare redirect rule.
- Produces: timestamped public HTTP evidence for the owner to attach to the migration log.

- [ ] **Step 1: Confirm the source of truth**

Read the canonical configuration and routes:

```ts
// src/config/site.ts
export const SITE_URL = "https://portfolio.huynhsang.id.vn";
```

```ts
// src/app/robots.ts
sitemap: `${SITE_URL}/sitemap.xml`,
```

Expected: every emitted canonical URL is derived from `SITE_URL`; no production code declares the apex as canonical.

- [ ] **Step 2: Run regression coverage**

Run:

```bash
bunx vitest run tests/unit/canonical-origin.test.ts tests/unit/site-config.test.ts
```

Expected: PASS, including robots, sitemap, RSS, and the canonical subdomain assertion.

- [ ] **Step 3: Capture redirect evidence**

Run:

```powershell
curl.exe -sS -I "https://huynhsang.id.vn/blog/sample-post-one?utm_source=p5-seo"
```

Expected headers:

```text
HTTP/1.1 308 Permanent Redirect
Location: https://portfolio.huynhsang.id.vn/blog/sample-post-one?utm_source=p5-seo
```

The response must have a single redirect, preserve both the path and query string, and not point to a `workers.dev` hostname.

- [ ] **Step 4: Capture canonical endpoint evidence**

Run:

```powershell
$targets = @(
  "https://portfolio.huynhsang.id.vn/robots.txt",
  "https://portfolio.huynhsang.id.vn/sitemap.xml",
  "https://portfolio.huynhsang.id.vn/feed.xml"
)
foreach ($target in $targets) {
  curl.exe -sS -L --max-redirs 2 -o NUL -w "$target status=%{http_code} final=%{url_effective}`n" $target
}
```

Expected: each target returns `status=200` with its own canonical URL as `final`.

- [ ] **Step 5: Record the secret-free baseline**

Create an owner-maintained log entry containing:

```text
Timestamp (UTC):
Canonical origin: https://portfolio.huynhsang.id.vn
Canonical sitemap: https://portfolio.huynhsang.id.vn/sitemap.xml
Legacy redirect sample:
Canonical endpoint results: robots / sitemap / feed
Search Console baseline: indexed pages, crawl errors, impressions, clicks
Bing baseline: indexed pages, crawl errors, impressions, clicks
```

Expected: the record contains no cookies, API keys, account identifiers, or screenshots that reveal private data.

### Task 3: Monitor, investigate, and escalate migration signals

**Files:**

- Inspect: `docs/deploy.md`
- Record: owner-maintained P5 migration log

**Interfaces:**

- Consumes: Task 1 baseline and Task 2 submission status.
- Produces: a scheduled evidence trail and a decision record for incidents or rollback approval.

- [ ] **Step 1: Review at defined checkpoints**

Review Search Console and Bing at:

```text
T+7 days
T+28 days
After any indexing, organic-traffic, or redirect alert
```

Compare against the baseline:

```text
Sitemap fetch/processing status
Indexed and excluded page counts
Crawl errors and URL inspection diagnostics
Canonical selection
Impressions, clicks, queries, and organic traffic
```

Expected: indexes converge on the portfolio subdomain; normal crawl/indexing latency is documented without triggering rollback.

- [ ] **Step 2: Classify defects before acting**

Escalate an incident only for evidence of:

```text
Redirect loop or redirect chain
Location header does not preserve equivalent path/query
Canonical URL points to the apex or an unrelated hostname
Persistent sitemap fetch failure
Persistent migration-attributable 4xx/5xx
Material indexing/coverage regression attributable to the migration
```

Expected: one-off indexing delay, incomplete early crawl discovery, or temporary console reporting lag is not classified as a rollback incident.

- [ ] **Step 3: Obtain explicit approval for any production remediation**

Before changing DNS, Cloudflare rules, `SITE_URL`, deployment configuration, or a sitemap route:

```text
1. Attach the HTTP and console evidence to the incident record.
2. State the candidate remediation and user impact.
3. Request owner approval for the exact remote or code change.
4. Verify the same Task 1 evidence after the approved change.
```

Expected: no automatic rollback is performed. Disabling the redirect or restoring a former canonical origin happens only after a systemic defect is proven and owner approval is recorded.
